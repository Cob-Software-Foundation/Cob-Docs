Overview

Cob is a corn-themed hybrid language with Python-style, indentation-and-colon block structure. A program is a sequence of statements; blocks (while, if, elif, else and recipe) are opened with a trailing : and their body is whatever's indented further than the header line. 

recipe countdown(n):
    while n > 0:
        pop("counting down: " + n)
        set n = n - 1
    serve "liftoff"

pop(countdown(3))

The language itself is small: variables, arithmetic, pop, while, if, recipe and shuck. Everything else — reading what the person types, text, numbers, time, files, SQLite, windows, Tcl/Tk — is the standard library: real shared libraries brought in with shuck, every name corn themed.

Indentation is spaces only — tabs are a hard error. Comments are whole lines starting with #; there are no trailing comments, so the notes written to the right of some examples on this page are explanation, not code you can paste.

The toolchain

ToolWhat it does
cob_interpInterprets a .cob file directly, with a fast-boot .strawberry bytecode cache — or, with no file, starts an interactive REPL. One interpreter: the core language only, with no vendor libraries, so it builds in about a second.
popcorn_compCompiles a .strawberry file to a real, standalone native executable. Handles the whole language, recipes and every standard library module included.
farmerThe package manager — installs .cob libraries from a static registry.
lib/The standard library: one shared library per module, with its .cob wrapper. Keep it next to the tools.

Language reference

pop("text")

Writes text to stdout followed by a newline.

pop("hello")          # hello
pop("line one\nline two")

Supported escapes inside the string literal: \\, \", \n, \t.

set <name> = <expr>

Assigns a value to a variable, creating it if it doesn't exist yet. A value is either an integer or a string. Expressions support + - * / with standard precedence (*// bind tighter than +/-) on two integers; + also concatenates when either side is a string, converting the other side to text first. 

set a = 2 + 3 * 4              # 14
set b = a - 1
set greeting = "count: " + a  # "count: 14"

while <condition>:

Loops while the condition is true. A bare expression is a truthiness test (nonzero); a comparison uses == != < > <= >=, and works the same way on two strings as it does on two integers. Loops nest to any depth and are capped at 10,000,000 iterations as a safety net against runaway/infinite programs. 

while a != 0:
    pop("tick")
    set a = a - 1

if / elif / else 0.0.7

if <condition>: runs its indented block when the condition is true. The condition is exactly what a while takes: a comparison (== != < > <= >=) on two integers or two strings, or a bare expression as a truthiness test (non-zero for an integer, non-empty for a string).

An if may be followed by any number of elif <condition>: blocks and then at most one else: block. They must sit at the same indentation as the if they belong to, and are checked top to bottom — only the first block whose condition is true runs, or the else block if none is. 

set score = 85
if score >= 90:
    pop("grade: A")
elif score >= 80:
    pop("grade: B")
else:
    pop("keep practicing")    # grade: B is printed instead

Blocks nest to any depth, inside each other and inside loops: 

set i = 1
while i <= 3:
    if i == 2:
        pop("two")
    else:
        pop(i)
    set i = i + 1
There is no separate and/or/not yet — a condition is a single comparison or truthiness test. To combine two tests, nest one if inside the other. An else or elif with no matching if directly above it at the same indentation is a syntax error, and so is an if line with no trailing :. Both cob_interp and popcorn_comp support it and print identical output. if, elif and else are reserved words.

recipe <name>(<params>): / serve [<expr>] 0.0.9

A recipe is a function — it works like Python's def — and serve hands a value back to whoever called it, like return. A call is name(a, b), and can be used anywhere an expression can, or on a line of its own. 

# serve hands a value back
recipe add(a, b):
    serve a + b

# a recipe that ends without serve gives 0
recipe greet(name):
    pop("Hello, " + name + "!")

recipe fact(n):
    if n <= 1:
        serve 1
    serve n * fact(n - 1)

pop(add(2, 3))
greet("Ada")
pop(fact(10))
  • Scope. A recipe's parameters, and every name it sets, are local to it, for its whole body, and start at 0. Any other name reads the global variable of that name. A recipe cannot assign a global — it hands results back with serve.
  • Top level, and hoisted. A recipe is defined at the top level of a program, never inside a while, if or another recipe. All recipes exist before the program starts, so a call may appear above its recipe, and recipes may call each other.
  • Checked before anything runs. A call to a name that is not a recipe or a library function, a wrong number of arguments, a duplicate recipe, or serve outside a recipe is an error with its line number, so a typo fails up front, not halfway through.
  • Order of evaluation. Arguments, and the two sides of an operator, are evaluated left to right — in popcorn_comp as well.
  • Recursion works, up to 500 calls deep; past that you get a warning and the call gives 0, rather than a crash.
  • Names. recipe and serve are reserved words. A recipe cannot share its name with an extern.
[cob_interp] error at line 5: recipe 'add' takes 2 arguments but 1 was given

shuck <library_name>

Loads <library_name>.cob and splices its statements in at that point, like a textual include. It looks, in order, in:

  1. the current directory,
  2. cob_modules/<library_name>/<library_name>.cob — the layout farmer harvest installs into,
  3. the standard library directory.

Circular imports and excessive nesting depth are rejected with a clear error. A file that defines recipes can only be shucked at the top level of a program. 

shuck greeter
shuck kernels
pop("back in the main program")
Because the current directory is searched first, a file of yours named like a standard library module (a porch.cob next to your program) is found before the real one. Name your own files accordingly.

extern <name>(<params>) from "<library>"

Binds a C function from a shared library, so it can be called like any other function. This is what the whole standard library is built on, and how you write your own module. <library> is a path ("./libmine.so") or a bare module name ("porch", found in the standard library directory). The parameter names are documentation: Cob does not check how many arguments a call passes. If the library, or the function in it, can't be found you get one warning for the library and the function evaluates to 0. 

extern double_it(n) from "./libdoubler.so"
pop(double_it(21))

harvest(<bytes>) / trash(<variable>)

Low-level manual memory: harvest(n) is an expression that allocates n bytes and returns an opaque integer handle; trash(v) frees the handle held in v. Both require the --no-gc flag — a program that uses either without it is refused outright by both cob_interp and popcorn_comp, not silently ignored. 

set p = harvest(64)
trash(p)
Handles are plain integers, not real pointers — Cob code can't do pointer arithmetic with them, only pass them to trash(). Double-free and unknown-handle use are reported as warnings, not crashes.

_MakeCache = False

If the literal first line of a .cob file is _MakeCache = False (whitespace/case-insensitive), the .strawberry fast-boot cache is disabled entirely for that file — neither read nor written. 

_MakeCache = False
pop("always reparsed fresh")

The REPL 0.0.9

Run cob_interp with no file to try Cob interactively (cob_interp --repl does the same). Variables and recipes persist from one input to the next. 

$ cob_interp
Cob 0.0.9 REPL -- :help for help, :quit or Ctrl-D to leave
cob> 1 + 2
3
cob> set x = 10
cob> recipe square(n):
...      serve n * n
...
cob> square(x)
100
cob> :quit
  • A bare expression prints its value — numbers plainly, strings in quotes so "5" and 5 look different. A recipe call that ends without serve prints nothing.
  • A line ending in : starts a block. Keep typing indented lines (the prompt becomes ...) and finish with a blank line.
  • Typing a recipe again replaces it. Mistakes print an error and the session carries on.
  • Commands: :help, :vars, :recipes (or :funcs), :load <file.cob>, :reset, :quit (or Ctrl-D).
  • cob_interp file.cob -i runs a file first and then stays in the REPL with everything it defined. A file that fails to start does not drop you into the REPL.
  • Prompts and the banner only appear on a real terminal, so cob_interp --repl < script.txt is scriptable.
The REPL is part of cob_interp only — not popcorn_comp, and not the browser build.

The standard library 0.0.9

Everything beyond the core language is a module: a real shared library (lib<name>.so on Linux, lib<name>.dylib on macOS, <name>.dll on Windows) plus a small <name>.cob wrapper of extern declarations. shuck <name> loads the wrapper, which loads the library. Every module and every function is corn themed.

Where the libraries live

In a lib/ folder next to the tools (cob_interp, popcorn_comp), or wherever the COB_STDLIB environment variable points. make builds it into bin/lib/; ship it beside the binaries. If a library can't be found you get one warning naming it, and its functions evaluate to 0 or "".

  • Forgetting a shuck is a clear error: 'kernel_len' is not defined -- it is in the standard library: add `shuck kernels` at the top.
  • Wrong arguments to a library function print a warning ([kernels] warning: kernel_slice() takes 3 arguments, got 2) and give a harmless default (0 or ""); they never crash. Library warnings are tagged with the module name.
  • The same in both tools. popcorn_comp links the same shared libraries and records the library folder as an rpath, so a compiled program behaves like the interpreted one, warnings included — but it must be linked dynamically, so keep lib/ where it was when you compiled (or set COB_STDLIB).
Not every module is in every build. The downloadable packages and the Docker image carry porch cornmath kernels almanac granary pantry; barn needs X11 and OpenGL to build and tassel is a long from-source build, so both are opt-in (make stdlib-barn, make stdlib-tassel). The browser playground has no shared libraries to load, so it compiles porch, cornmath, kernels and almanac in and makes the rest quiet no-ops with a one-time notice.

porch — console input

shuck porch. Reads from standard input, so a program can be fed from a file or a pipe: cob_interp quiz.cob < answers.txt.

CallReturns
porch_ask(<prompt>)string — the line typed, without its line ending; "" at end of input
porch_ask_int(<prompt>)int — the line parsed as a whole number; 0 if it isn't one, or at end of input
shuck porch
set name = porch_ask("What is your name? ")
pop("Nice to meet you, " + name + "!")
set age = porch_ask_int("How old are you? ")
set next_year = age + 1
pop("Next year you will be " + next_year)
  • The prompt is optional, and can be a string or a number. It is printed without a trailing newline and flushed before reading, so it appears on the same line as the answer.
  • End of input — a piped file that has run out, or Ctrl-D (Ctrl-Z on Windows) — makes porch_ask() return "" and porch_ask_int() return 0.
  • porch_ask_int parsing. Spaces or tabs around a base-10 number are fine, and so is a leading - or +. Anything else, including a blank line, gives 0; a non-blank non-number also prints [porch] warning: porch_ask_int() got non-numeric input "abc"; treated as 0 on stderr.
  • Windows line endings (\r\n) are stripped.
Watch the end of input. A loop that waits for the right answer, such as while guess != secret:, can't tell "the right answer" from "no more answers": once the input runs out porch_ask_int keeps returning 0. Make sure the loop has another way out.

cornmath — numbers

shuck cornmath. All arguments and results are integers.

CallReturns
husk_abs(n)absolute value
ear_max(a, b) / ear_min(a, b)the larger / smaller of two numbers
stalk_pow(base, exp)base to a whole-number power; 0 (with a warning) for a negative exponent
stalk_sqrt(n)square root rounded down; 0 (with a warning) for a negative number
silk_mod(a, b)remainder with the sign of b (so silk_mod(0 - 7, 3) is 2); 0 (with a warning) when b is 0

scatter_rand uses its own generator, so a seeded run gives the same numbers on every platform. Unseeded, it starts from the clock.

granary — files

shuck granary. Text files only: contents are read up to the first zero byte.

pantry — SQLite

shuck pantry. The SQLite amalgamation is compiled into the library. Up to 16 databases can be open at once.

CallReturns
pantry_open(path)handle (int), 0 on failure. ":memory:" opens a database that lives only in memory.
pantry_exec(h, sql)0 on success, -1 (with a warning) on failure — for statements that give no answer
pantry_query(h, sql)string — first column of the first row, "" if none
pantry_close(h)0
shuck pantry
set h = pantry_open("scores.db")
set rc = pantry_exec(h, "CREATE TABLE IF NOT EXISTS t (name TEXT)")
set rc = pantry_exec(h, "INSERT INTO t VALUES ('cob')")
set name = pantry_query(h, "SELECT name FROM t LIMIT 1")
pop("got: " + name)
set rc = pantry_close(h)
Using a handle after pantry_close (or one that was never opened) warns and gives -1 / "" — it does not crash.

barn — a native window

shuck barn. Backed by raylib + raygui. Needs a display, and the barn library, which is opt-in to build (make stdlib-barn).

CallReturns
barn_open(title)handle (1), 0 on failure (for example, no display)
barn_label(h, text)0 — sets/replaces the window's text
barn_wait(h, seconds)0 — keeps the window responsive for about seconds
barn_close(h)0
barn_button(h, label)1 if clicked since the last read of that label, else 0
barn_slider(h, label, max)current value, 0 to max, as an int
barn_textbox(h, label)current string contents of the box
shuck barn
set h = barn_open("Cob Window Demo")
set rc = barn_label(h, "Hello from Cob!")
set clicked = barn_button(h, "OK")
set volume = barn_slider(h, "Volume", 100)
set name = barn_textbox(h, "Name")
set rc = barn_wait(h, 5)
set rc = barn_close(h)

Widgets are identified by their label: the first barn_button()/barn_slider()/barn_textbox() call with a given label creates it, stacked below the barn_label() text; every later call with the same label reads it (a slider is re-ranged, and its value clamped, if called again with a different max). Up to 16 widgets per window.

  • barn_button()'s click flag resets on read, so a click is reported exactly once.
  • barn_textbox() is always editable — there is no click-to-focus.
Only one native window per process — calling barn_open() again before closing the first warns and returns 0. The window's own close button ([X]) is intentionally ignored: the window stays open until barn_wait()'s timer runs out or barn_close() is called explicitly. Running more than one barn_textbox() at a time hasn't been verified for keyboard-focus behavior; treat that as unverified rather than unsupported.

tassel — Tcl and Tk

shuck tassel. One process-wide Tcl interpreter: variables and widgets persist between calls.

CallReturns
tassel_tcl(script)string — Tcl's own string result
tassel_tk(script)string — the same interpreter, with Tk also loaded
shuck tassel
pop("answer=" + tassel_tcl("expr {6*7}"))
Opt-in to build (make stdlib-tassel): it compiles the vendored Tcl/Tk, and needs TCL_LIBRARY pointed at Tcl's library folder at run time. tassel_tk() needs a real X11 $DISPLAY; without one it evaluates to a normal Tcl error string, the same as real Tk would report, not a crash.

silo — the everyday five

shuck silo is just shuck porch, cornmath, kernels, almanac and granary together. The heavier modules (pantry, barn, tassel) are shucked on their own.

Upgrading from 0.0.8

The built-in input, SQLite, window and Tcl/Tk keywords are gone; they are standard library functions now. An old name gives an error that says exactly what to write instead ('input' is now porch_ask() in the standard library: add `shuck porch` at the top and call porch_ask(...)).

0.0.80.0.9
input(p) / input_int(p)shuck porch, then porch_ask(p) / porch_ask_int(p)
sql_open sql_exec sql_query sql_closeshuck pantry, then pantry_open pantry_exec pantry_query pantry_close
shuck cobwindow + window_open window_label window_wait window_close window_button window_slider window_textboxshuck barn, then barn_open barn_label barn_wait barn_close barn_button barn_slider barn_textbox
tcl_eval / tk_evalshuck tassel, then tassel_tcl / tassel_tk

Also new: recipe and serve are reserved words; the .strawberry cache format changed (old caches are rebuilt automatically); and cob_interp_full, cob_interp_db and cob_interp_window are no longer different builds — there is one interpreter, and those names are kept only as make targets for old scripts. See the release notes for everything.

Write your own module

A module is the same thing the standard library is: a shared library whose functions all have one shape, plus a wrapper that declares them. Include include/cob.h from the Cob source. 

/* doubler.c */
#include "cob.h"

COB_EXPORT CobValue double_it(CobValue *argv, int argc) {
    if (argc != 1 || argv[0].kind != COB_INT) return cob_int(0);
    return cob_int(argv[0].as.i * 2);
}
cc -shared -fPIC -Iinclude -o libdoubler.so doubler.c
# doubler.cob -- the wrapper
extern double_it(n) from "./libdoubler.so"
shuck doubler
pop(double_it(21))

Values are COB_INT (as.i) or COB_STR (as.s); make one with cob_int(n) or cob_str(text). Cob copies a returned string immediately, so return a literal, a static buffer, or a buffer you keep alive until your next call — never free it for Cob. Put the library and wrapper in the standard library folder and from "doubler" works too.

Tool reference

cob_interp

cob_interp [file.cob] [--no-cache] [--no-gc] [-i]
(no file)Start the interactive REPL.
-i, --replRun the file, then stay in the REPL with everything it defined.
--no-cacheSkip reading/writing the .strawberry cache for this run.
--no-gcUnlock harvest()/trash().

One interpreter, the core language only. Console input, text, SQLite, windows and the rest are standard library modules you shuck; porch_ask() reads standard input, so a program can be fed from a file or a pipe: cob_interp quiz.cob < answers.txt.

The .strawberry cache format is version COBSTRW10; caches written by earlier releases are detected and rebuilt.

popcorn_comp

popcorn_comp <file.strawberry> -o <output> [--no-gc] [--cc <compiler>] [--emit-c <path.c>]

Transpiles the bytecode to plain C, then spawns a real C compiler to produce a native executable. Default backend is Zig's zig cc — a Clang-based drop-in C compiler that bundles libc/CRT files for essentially every target in one install, which is what makes CobOS/CobArch cross-compiling a plain -target flag instead of needing a separately installed cross-toolchain per platform. Release downloads bundle Zig in a zig/ folder next to popcorn_comp and find it automatically, so nothing else needs installing; when building from source, put Zig on your PATH or pass --cc.

Compiler is resolved in this order:

--cc <path>Explicit override, always wins.
$CobCCEnvironment variable override.
$CobOS / $CobArchLooked up in a table of Zig target triples.
zig ccDefault: native compile, Zig auto-detects the host.
CobOS=windows CobArch=amd64 popcorn_comp prog.strawberry -o prog.exe
# -> spawns: zig cc -target x86_64-windows-gnu ...
Linux cross-compile targets default to musl libc rather than glibc, producing fully static binaries with no runtime libc dependency (see the note below about the standard library).
Recipes and every standard library module compile, because library calls are ordinary shared-library calls: the finished program is linked with -l<module> and the standard library folder is recorded as its rpath. Two consequences: the program must be linked dynamically (a static program can't use shared libraries — and the Linux musl targets above are static), and a cross-compiled program needs those modules built for its target, with COB_STDLIB pointing at them when you compile. Programs that use only the core language are unaffected.
Without --cc or $CobCC, popcorn_comp looks for zig cc. If you don't have Zig, name your C compiler: CobCC=cc popcorn_comp prog.strawberry -o prog.

farmer

farmer harvest <package>

Fetches {registry}/api/v1/packages/<package>.json, verifies the metadata's name field matches what was requested, downloads the package zip, verifies its sha256 if one was provided, and unzips it into cob_modules/<package>/ — ready for shuck <package>.

$COB_FARMER_BASE_URLOverride the registry base URL.

The registry itself lives at Cob-Software-Foundation/cpi, served for free via GitHub Pages — no server, just static JSON files.

Docker 0.0.9

GitHub Actions builds, tests and publishes a container image (linux/amd64 and linux/arm64) with the interpreter and REPL, popcorn_comp, farmer and the standard library — everything except barn and tassel, which need a display or a long from-source build. 

docker run -it --rm ghcr.io/cob-software-foundation/cob
docker run --rm -v "$PWD:/work" ghcr.io/cob-software-foundation/cob hello.cob
docker run --rm -v "$PWD:/work" ghcr.io/cob-software-foundation/cob popcorn_comp hello.strawberry -o hello
  • The first command is the REPL. Anything that is not the name of another tool in the image (popcorn_comp, farmer, sh) goes to cob_interp.
  • The image runs as an unprivileged user. To read and write your own files as yourself add --user "$(id -u):$(id -g)".
  • A program compiled inside the image is for the image (its glibc, its lib/): run it there with --entrypoint /work/hello rather than copying it to another machine.
  • Build it yourself with docker build -t cob .; the build runs the whole test suite.
